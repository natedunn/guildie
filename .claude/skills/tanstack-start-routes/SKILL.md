# TanStack Start routes in Guildie

File routes in `apps/web/src/routes/`; `routeTree.gen.ts` is generated by the
Vite plugin while `pnpm dev` runs (commit it). Path params are `$name`
(`g/$region/$slug.tsx` is `/g/us/unbound`).

## Main routes

| Route                                                                                                 | Page                                                                                                       |
| ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `__root.tsx`                                                                                          | HTML shell, app shell (sidebar, title bar, content pane), auth provider, `?item=` panel, desktop detection |
| `index.tsx`                                                                                           | Home: find or add a guild                                                                                  |
| `g/$region/$slug.tsx` + `g/.../index.tsx`, `crafting.tsx`, `gear.tsx`, `dungeons.tsx`, `requests.tsx` | A guild: layout with header; its pages are in the sidebar (Dungeons and Requests for members)              |
| `c/$region/$slug.tsx` + `index.tsx`, `talents.tsx`, `professions.tsx`                                 | A character: layout with tabs (`inventory.tsx` only redirects to `/inventory`)                             |
| `inventory.tsx`, `quests.tsx`                                                                         | Personal (sidebar, signed in): your characters' bags and banks; their quests and who shares them           |
| `settings.tsx` + `settings/{index,guilds,addon,app}.tsx`                                              | Settings tabs (Addon and App are for the desktop app)                                                      |
| `sign-in.tsx`, `claim/callback.tsx`, `desktop/session.tsx`, `helper/connect.tsx`, `auth/*`            | Sign-in flows (auth-and-sign-in skill; ask first)                                                          |
| `api/helper/*`                                                                                        | HTTP endpoints for the desktop app (server routes)                                                         |

## Reading data: loader + suspense

The loader warms the query cache (on the server during SSR), the component
reads the same query with `useSuspenseQuery`, and it stays live over the
Convex websocket.

```tsx
import { convexQuery } from "@convex-dev/react-query";
import { api } from "@convex/_generated/api";
import type { Region } from "@convex/shared/wow";
import { useSuspenseQuery } from "@tanstack/react-query";
import { createFileRoute, notFound } from "@tanstack/react-router";

export const Route = createFileRoute("/g/$region/$slug")({
	loader: async ({ context, params }) => {
		const data = await context.queryClient.ensureQueryData(
			convexQuery(api.guilds.get, { region: params.region as Region, slug: params.slug }),
		);
		if (!data) throw notFound();
		return { name: data.guild.name }; // used by head() and breadcrumbs
	},
	head: ({ loaderData }) => ({ meta: [{ title: `${loaderData?.name ?? "Guild"} · Guildie` }] }),
	component: GuildLayout,
});

function GuildLayout() {
	const params = Route.useParams();
	const { data } = useSuspenseQuery(convexQuery(api.guilds.get, { region: params.region as Region, slug: params.slug }));
	...
}
```

- Same function and **identical args** in loader and component, or the
  component suspends again.
- Child routes under a layout can read the parent's query without a loader
  (`g/$region/$slug/index.tsx`).
- `useQuery(convexQuery(...))` (non-suspense) only for optional, client-only
  bits (`sign-in.tsx`'s `guestEnabled`).

## Writing data

`useMutation(api.x.y)` / `useAction` from `convex/react`. Catch `ConvexError`
and show `error.data` (it's written for the user). Queries update by
themselves after a mutation; no refetching.

## Layouts and tabs

A layout route renders shared chrome and `<Outlet />`. Tabs that are routes
use `PageTabs`/`PageTab` (`components/page-tabs.tsx`); every page starts with
`PageHeader` and wraps its body in `Page` (`components/page-header.tsx`).

## Search params

Validate them in `validateSearch` and read with `Route.useSearch()`; update
with `navigate({ search: (prev) => ({ ...prev, q }), replace: true, resetScroll: false })`
(see `g/$region/$slug/crafting.tsx`). The root owns `?item=<id>`, which opens
the item panel over any page (`components/item-sheet.tsx`); keep `...prev`
so you don't drop it.

## Titles and breadcrumbs

`head()` sets `"<Name> · Guildie"`. The title bar's breadcrumbs
(`src/lib/breadcrumbs.ts`) come from matched routes' `loaderData` (`name`,
`guild`) and `TAB_LABELS`; a new tab route needs an entry there.

## SSR, the browser and the Windows app

- The root `beforeLoad` gets the auth token (`getAuthToken`) and
  `readDesktopInfo()`, which parses ` GuildieDesktop/<version>` (and
  ` (Mica)`) from the **user agent**, on the server too. So
  `<html data-desktop="true">` is right on first paint. Use
  `useInDesktopApp()` (`src/lib/desktop.ts`) in components; never
  `typeof window` checks for layout (hydration mismatch).
- The bridge (`window.guildieDesktop`) exists only in the app and only in the
  browser: get it with `desktop()` inside effects or handlers. Its newer
  methods are optional (older app versions); check before calling.
- To see the app layout in a browser: override the user agent (devtools), or
  `curl -sk -A "Mozilla/5.0 GuildieDesktop/0.3.5" <local url>`.
- The page never scrolls; `#content` does. The router restores scroll for
  `#content` (`router.tsx`).

## Gotchas

- `@convex/...` and `@/...` are path aliases (`tsconfig.json`).
- Route params are strings; cast `region` to `Region` and let the Convex
  validator reject bad ones, or `notFound()` when the query returns null.
- Server routes (`api/helper/*`) run on the Cloudflare Worker and call Convex
  with `ConvexHttpClient` (`src/lib/helper-api.ts`); they have no runtime
  secrets.
